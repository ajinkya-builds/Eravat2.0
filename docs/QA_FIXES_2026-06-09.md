## Detailed Changes

### S-3 — Grain damage double-count
**File:** `eravat-app/src/services/adminAnalyticsService.ts` (`countDamages`)

A report with `conflict_damages.category = 'grain'` whose description also matched `/grain/i` was counted twice: once in the per-damage loop, and again via `counts.grain += grainReports.size`. The deduplication block only protected `counts.total`, not `counts.grain`.

**Fix:** Build an `alreadyCountedGrain` set of report IDs that have an explicit `grain` category, then only add inference-derived grain reports that are **not** already in that set. Both `counts.grain` and `counts.total` now use the deduplicated `newGrainReports` count.

```ts
const alreadyCountedGrain = new Set(
    reports.filter(r =>
        (r.conflict_damages ?? []).some(d => mapDamageCategory(d.category ?? '') === 'grain')
    ).map(r => r.id)
);
const newGrainReports = [...grainReports].filter(id => !alreadyCountedGrain.has(id));
counts.grain += newGrainReports.length;
if (newGrainReports.length) {
    counts.total += newGrainReports.length;
}
```

### H-2 — `status:'pending'` hardcoded on every upsert
**File:** `eravat-app/src/services/syncService.ts` (reports upsert in `syncData`)

Every report upsert wrote `status: 'pending'`, which would clobber an admin's server-side `approved`/`rejected` status back to `pending` on any future edit-and-resync flow.

**Fix:** Removed the `status` field from the upsert payload entirely. The server column default handles new rows; existing server statuses are now preserved on retry.

### H-3 — FNV-1a UUID derivation collision-fragile
**File:** `eravat-app/src/services/syncService.ts` (`stableHex32`)

All four UUID segments were derived from a single 32-bit FNV-1a hash via multiplicative mixing. If two different inputs collided on that one 32-bit hash, all four segments became identical, producing the same UUID and silently overwriting one report's `observations`/`conflict_damages` row with another's.

**Fix:** Rewrote `stableHex32` to run four **independent** FNV-1a hashes over distinct inputs (the original string plus 1, 2, and 3 trailing NUL bytes). Each UUID segment is now an independent 32-bit hash, so a single-segment collision no longer cascades to the whole UUID.

```ts
function stableHex32(input: string): string {
    function fnv1a32(s: string): number {
        let h = 2166136261;
        for (let i = 0; i < s.length; i++) {
            h ^= s.charCodeAt(i);
            h = Math.imul(h, 16777619);
        }
        return h >>> 0;
    }
    const h1 = fnv1a32(input).toString(16).padStart(8, '0');
    const h2 = fnv1a32(input + '\x00').toString(16).padStart(8, '0');
    const h3 = fnv1a32(input + '\x00\x00').toString(16).padStart(8, '0');
    const h4 = fnv1a32(input + '\x00\x00\x00').toString(16).padStart(8, '0');
    return `${h1}${h2}${h3}${h4}`;
}
```

> **Note:** Existing unsynced local reports keep their old deterministic `obs_id` and continue to work on retry (idempotent upsert by the stored key). No server-side cleanup needed.

### H-4 — Phone enumeration via `message` field
**File:** `eravat-app/src/contexts/AuthContext.tsx` (`signInWithPhoneOTP`)

While the user-facing `error` messages were generic, the returned `message` field exposed distinct values (`user_not_found`, `rate_limit`, `send_failed`, `unexpected_error`) that let a caller distinguish "number not registered" from other failure modes — enabling phone-number enumeration.

**Fix:** All non-success return paths now return `message: 'failed'`. The success path retains `message: 'otp_sent'`. Internal diagnostics remain available through `console` logging only.

> **Caller impact:** `Login.tsx` previously special-cased `message === 'rate_limit'` to show a localized "too many requests" string. That branch now falls through to the (already user-friendly) `error.message`: *"Too many requests. Please try again later."* The behavior is still meaningful, just no longer localized for this one case — an acceptable trade-off for closing the enumeration vector.

### M-1 — `wasAuthenticated` used `useState` as a ref
**File:** `eravat-app/src/contexts/AuthContext.tsx`

`const wasAuthenticated = useState({ current: false })` worked only because React preserves the object reference when the setter is never called. Direct mutation of a state object bypasses React's model and is fragile under concurrent / strict-mode rendering.

**Fix:** Replaced with `const wasAuthenticated = useRef(false)`. All four read/write sites updated from `wasAuthenticated[0].current` → `wasAuthenticated.current`.

### M-3 — Division filter applied client-side after the 2000-row limit
**File:** `eravat-app/src/services/adminAnalyticsService.ts` (`fetchAdminReports`)

The function fetched up to 2000 rows unfiltered, then filtered by `divisionId` in JavaScript. With more than 2000 reports in range, a selected division's reports beyond the cut-off were silently dropped.

**Fix:** Moved the division filter server-side using the same beat-ID resolution pattern already used in the admin pages: resolve `geo_ranges → geo_beats` for the division, then apply `.in('beat_id', beatIds)` **before** the `.limit(2000)`. Empty range/beat sets short-circuit to an empty result. The client-side `.filter()` was removed entirely.

### M-4 — Silent `catch {}` hid profile fetch errors
**File:** `eravat-app/src/contexts/AuthContext.tsx` (`fetchProfile`)

```ts
} catch {
    // Profile fetch failed
}
```

Any exception inside `fetchProfile` was swallowed, leaving the profile state at its previous (possibly stale) value — a user with corrupted profile data would appear authenticated with the wrong data.

**Fix:** The catch block now logs the error and clears profile state:

```ts
} catch (err) {
    console.warn('[AuthContext] fetchProfile threw:', err);
    setProfile(null);

```

### L-1 — Dead-code branch in `verifyOTP`
**File:** `eravat-app/src/contexts/AuthContext.tsx` (`verifyOTP`)

`normalisePhone` always returns ≤10 digits for Indian numbers, so the `storedDigits.length === 12 && startsWith('91')` guard could never be true. The dead branch masked future phone-format regressions.

**Fix:** Removed the unreachable conditional. The E.164 number is now constructed in a single line:

```ts
const tenDigit = normalisePhone(phone);
const e164Phone = `+91${tenDigit}`;
```

### L-2 — No-op date math
**Files:** `eravat-app/src/pages/admin/AdminConflict.tsx`, `eravat-app/src/pages/admin/AdminGeneral.tsx`

`startOfMonth(parseISO(\`${start}-01\`.slice(0, 10)))` — `start` is already `YYYY-MM-DD`, so appending `-01` then slicing to 10 chars returned the same string. Functionally correct (because `startOfMonth` compensated) but misleading.

### L-4 — Cross-tab sync lock TOCTOU
**File:** `eravat-app/src/services/syncService.ts`

`tryAcquireCrossTabSyncLock` read `localStorage`, evaluated the lock, then wrote — a non-atomic read-then-write where two tabs could both observe "no lock" and both proceed.

**Fix:** `tryAcquireCrossTabSyncLock` is now `async` and uses the **Web Locks API** (`navigator.locks.request(..., { ifAvailable: true })`) for a true atomic cross-tab lock when available, falling back to the original `localStorage` approach in environments without the API. The held lock's release callback is stored in a module-level `_webLockResolve` and invoked by `releaseCrossTabSyncLock`. `syncData` now `await`s the lock acquisition.

### L-5 — Async `useEffect` cleanup registered a duplicate listener
**File:** `eravat-app/src/App.tsx` (`NetworkSync`)

```ts
return () => { listener.then(l => l.remove()); };
```

`Network.addListener` returns a Promise. The async cleanup meant that during React Strict Mode's double-mount, the first mount's listener was still active when the second registered, causing `networkStatusChange` to fire twice → two concurrent `syncData()` calls.

**Fix:** Used a cancellation-flag pattern. The handle is stored once the promise resolves; cleanup sets `cancelled = true` and calls `handle?.remove()` synchronously. If the promise is still pending at cleanup time, it removes its own listener on resolution.

```ts
let cancelled = false;
let handle: Awaited<ReturnType<typeof Network.addListener>> | null = null;
Network.addListener('networkStatusChange', status => {
  maybeSync(status.connected, status.connectionType);
}).then(h => {
  if (cancelled) { h.remove(); } else { handle = h; }
});
return () => {
  cancelled = true;
  handle?.remove();
};
```
