## 3. Detailed Findings (by Severity)

### S1 — Blockers (must fix before launch)

#### S1.1 — Production build is broken
**Files:**
- `eravat-app/src/pages/admin/AdminConflict.tsx`
- `eravat-app/src/pages/admin/AdminGeneral.tsx`
- `eravat-app/src/pages/admin/AdminLive.tsx`

**Symptoms:** `npm run build` exits with 27 TypeScript errors. CI deploy will fail. Representative errors:

```
src/pages/admin/AdminConflict.tsx(153,30): error TS7009: 'new' expression, whose target lacks a construct signature, implicitly has an 'any' type.
src/pages/admin/AdminConflict.tsx(193,19): error TS2322: Type 'unknown[]' is not assignable to type 'PiePoint[]'.
src/pages/admin/AdminGeneral.tsx(275,29): error TS2345: Argument of type 'unknown[]' is not assignable to parameter of type 'SetStateAction<DivisionRow[]>'.
src/pages/admin/AdminLive.tsx(152,40): error TS7009: 'new' expression, whose target lacks a construct signature, implicitly has an 'any' type.
src/services/__tests__/SyncService.extended.test.ts(18,7): error TS6133: 'mockEq' is declared but its value is never read.
```

**Root cause:** `new Map(...)` lacks explicit type arguments, so `Array.from(map.values())` is `unknown[]`; downstream `.sort` / `setState` calls fail.

**Fix:** Annotate `Map<string, LinePoint>()`, `Map<string, DivisionRow>()`, `Map<string, number>()` everywhere they're constructed; remove `as any` casts; delete two unused vars in `SyncService.extended.test.ts`.

**Effort:** 1–2 hours. **Re-test:** `npm run build && npm run test:run`.

---

#### S1.2 — `test_notif.ts` at app root leaks PII to console
**File:** `eravat-app/test_notif.ts`

A debug script using the anon key that queries `profiles` (id + phone) and `notifications`, then `console.log`s the rows. It is untracked but sits inside the Vite source root. If accidentally imported or built it would leak user phone numbers.

```ts
const { data: users } = await supabase.from('profiles').select('id, phone').limit(5);
console.log("Users:", users);
```

**Fix:** Delete it, or move it to `scripts/` outside the Vite root and add to `.gitignore`. **Effort:** 1 minute.

---

#### S1.3 — Three new admin pages are dead code that breaks the build
**Files (untracked):** `AdminConflict.tsx`, `AdminGeneral.tsx`, `AdminLive.tsx`

Routes in `src/App.tsx:106-107` still point at the **old** `AdminConflictDashboard` and `AdminLiveDashboard`. The three new files are unreferenced *and* contain all 25+ TS errors that block the build.

**Decision required from PM:** are these (a) replacements for the old dashboards, (b) prototypes to inform a future migration, or (c) abandoned drafts?

- If (a): wire them into routes, delete old files, fix TS errors.
- If (b): move to a `experimental/` folder excluded from `tsconfig`.
- If (c): delete.

**Effort:** 30 min decision + 1–4 h depending on choice.

### S2 — Critical (should fix before launch)

#### S2.1 — `SyncService` overwrites server `status` on every report sync
**File:** `eravat-app/src/services/syncService.ts:249`

```ts
.upsert({
    id: report.id,
    user_id: report.user_id,
    ...
    status: 'pending',     // ← hardcoded on every upsert
});
```

Today this is safe because reports re-sync only when locally `pending` / `failed`. **Latent risk:** if any future edit-and-resync flow resets a previously-`synced` report to `pending`, an admin's `approved` / `rejected` server status gets clobbered back to `'pending'`.

**Fix:** omit `status` from the upsert payload, or use `onConflict: 'id'` with an explicit column list. Add a regression test.
**Effort:** 2 h including test.

---

#### S2.2 — `AdminLive` pulls all notifications client-side, unscoped
**File:** `eravat-app/src/pages/admin/AdminLive.tsx:146-149`

```ts
let notifQ = supabase.from('notifications')
  .select('id, user_id, report_id')
  .gte('created_at', since);
const { data: allNotifs } = await notifQ;
```

No `beat_id` / division filter, no `.limit()`. Scales linearly with notification volume. Two problems:
1. **Performance:** admin page will slow down or OOM the browser at scale.
2. **Privacy:** depends entirely on RLS to scope `notifications` per admin; if RLS is permissive for admin role, every admin sees every recipient's `user_id`.

**Fix:** push count + distinct-recipients to a Postgres function (or aggregated view) filtered by division. **Effort:** 4 h.

---

#### S2.3 — `wasAuthenticated` uses `useState` instead of `useRef`
**File:** `eravat-app/src/contexts/AuthContext.tsx:64`

```ts
const wasAuthenticated = useState({ current: false });
// ...
wasAuthenticated[0].current = true;   // direct mutation of state object
```

Works today only because React preserves the reference; semantically wrong. Will surprise any maintainer and is fragile under React strict-mode / concurrent rendering changes.

**Fix:** `const wasAuthenticated = useRef(false);` and update the two read/write sites. **Effort:** 5 min.

---

#### S2.4 — Bundle size: 1.8 MB JS / 516 KB gzip
Vite warns the main chunk exceeds 500 kB after minification. The deployment context is a forest-staff PWA on rural 3G — slow first paint is a real problem.

**Fix:** route-level `React.lazy()` for `/admin/*`, lazy-load Recharts and Leaflet. **Effort:** 4–6 h, large TTI win.

### S3 — Major (fix in first post-launch sprint)

#### S3.1 — 53 unguarded `console.*` calls in production paths
Concentrated in `AuthContext.tsx`, `syncService.ts`, `ReportStepper.tsx`. Most are diagnostic. Wrap with `if (import.meta.env.DEV)` or remove.

#### S3.2 — 112 ESLint errors
Bulk are `@typescript-eslint/no-explicit-any` in test mocks and `no-unused-vars` in Playwright tests/page objects. None block runtime but CI lint gate is broken. Note also `react-hooks/rules-of-hooks` violations in `tests/fixtures/auth.fixture.ts` from functions named `use*` that aren't hooks — rename.

#### S3.3 — Documented schema gaps in admin dashboards
`AdminConflict` / `AdminGeneral` / `AdminLive` hardcode `0` for *Human Death*, *Human Injury*, and *Grain Damage* with `⚠ Schema` badges. The comments are explicit:

```
// SCHEMA NOTES (⚠️ = gap):
//   - Human Death:  ⚠️  Not in loss_category enum or LOSS_TYPES. Shows 0.
//   - Human Injury: ⚠️  Same. Shows 0.
//   - Grain Damage: ⚠️  Not a tracked loss_type. Shows 0.
```

This is honest but PM should explicitly sign off on shipping a dashboard with permanently-zero KPIs for v1.

#### S3.4 — Buggy date math in `AdminConflict`
`src/pages/admin/AdminConflict.tsx:154`:
```ts
let cur = startOfMonth(parseISO(`${start}-01`.slice(0, 10)));
```
`start` is already `YYYY-MM-DD`. Appending `-01` then slicing to 10 chars is a no-op. Likely intent was `${start.slice(0,7)}-01` to snap to the first of the month. Works today because `startOfMonth` is applied anyway.

#### S3.5 — `.env.example` ships the project's real publishable key
`eravat-app/.env.example:6` contains `VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_…`. This is *intentional* for publishable keys (RLS is the security gate), but reviewers should re-confirm RLS covers every new table introduced in the recent migrations. Spot-check passed for the territory-scoped policies via `can_read_report(uuid)`.

## 4. What Looks Good ✅

- **Unit tests:** 116/116 pass. Strong coverage on `SyncService` (concurrency mutex, MIME validation, base64 corruption, RLS-denied paths) and `adminAnalyticsService` (51 tests).
- **RLS hardening** migrations (territory-scoped policies, `profiles` ↔ `auth.users` sync, notification hardening) are present and look correct on a spot-check.
- **Edge functions** (`update-user`, `create-user`, `send-push`) verify caller identity *and* check the caller's role *before* using the service-role key — no anon-key privilege-escalation paths visible.
- **Phone / OTP login** uses an RPC indirection (`get_email_by_phone`) to avoid user enumeration; error messages are generic.
- **Sync security:** validates `report.user_id === auth.user.id`, enforces a safe-ID regex (`/^[a-zA-Z0-9_-]+$/`), enforces a MIME-type allowlist, and verifies the report exists server-side before writing media rows.
